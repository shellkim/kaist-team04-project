# Feature Spec — 스킨 체크리스트 (Skin Checklist)

Author: Eunhye Hyun (현은혜)
Date: 2026-10-28
Status: decided

한 줄: 앱을 열면 오늘 해야 할 일이 이미 있다. 유저는 문구를 쓰지 않고 박스만 깬다. 다 깨면 All Clear.

---

## Who it is for, and the moment the problem shows up

**Who:** 시술에 돈을 쓰지만, 매일 뭘 해야 하는지 다시 생각하고 싶지 않은 20–40 워킹우먼.

**Moment:** 아침, 또는 시술 다음 날. 병원 안내는 이미 치웠고, 자외선·보습·마찰을 오늘 다시 검색하기 직전에 앱을 연다.

시술이 없어도 이 순간은 있다. 평상시 데일리 박스가 바로 있어야 한다.
받을지 미룰지를 적는 사람은 이 화면의 주 사용자가 아니다.

홈 고정 문구: 이 앱은 개인용 할 일 도우미다. 의료 조언, 진단, 회복 판정이 아니다. 병원 안내와 다르면 병원 안내가 우선이다.

뿌리는 `지속가능한 최상의 나, Best Self`. 화면에 그리지 않는다. 예보 한 줄은 `자신감 & 사회적 가치`가 아니다.

이 스펙이 이 노드를 **안 만든다:** `데일리 스킨케어 자극 지수 분석`, `셀카 기반 전후 효과 데이터 트래킹`, `다음 적정 시술 및 주기 추천`(다른 시종), `유사 피부 고민 후기`.

이 개인 스펙은 팀 `PROJECT.md`(전후 사진, AI 시각 분석, 또래 통계)와 갈라진다.

## Core logic — 오늘 목록을 고르는 방법

화면에 `Engine` / `회복 모드` / `데일리 데이펜스` 같은 이름은 쓰지 않는다. 유저는 모드를 고르지 않는다. 시술 날짜만 보면 된다.

```
앱을 연다
  → 시술일부터 N이 6 이하인가?
      yes → 그 종류 회복 목록 (초반 N=0–2 / 후반 N=3–6)
      no  → 데일리 3개
  → 오늘 체크리스트
```

- 시술일 = D+0. 활성 시술 1개 (시술일 ≤ 오늘인 것 중 가장 최근).
- N ≥ 7이면 데일리로 바꾼다.
- 오늘 = 브라우저 로컬 날짜.

**해야 할 일:** 체크박스. 문구는 고칠 수 없다.

**하지 말아야 할 일:** 회복 중에만 보인다. **체크 불가.** 제목 `오늘 참고`. 예: `술 안 마시기`, `사우나 안 가기`. All Clear에 넣지 않는다.

날씨는 상단 예보 한 줄만 바꾼다. 체크 항목을 더하거나 문구를 바꾸지 않는다.

## What the user can do, step by step

1. 앱을 연다. 시술 입력을 강제하지 않는다.
2. 상단에 예보 mock 한 줄. `예시`. 자외선·습도. 실제 날씨가 아니다.
3. 오늘 해야 할 일 3개가 이미 있다. 세안, 선크림, 보습. 모두 미체크.
4. 박스 하나를 깬다.
5. 세 개를 모두 깨면 같은 화면에 `오늘 케어 All Clear`. 새 페이지·점수·셀카·연속 일수 없음.
6. (선택) 아래 `시술 추가`: 날짜, 이름, 카테고리 **하나** (P0는 두 종류만).
7. 저장하면 목록이 그 종류 회복 할 일로 바뀐다. 아래에 `오늘 참고`가 생긴다. 참고는 체크할 수 없다.
8. 날짜가 바뀌면 체크만 리셋된다. N ≥ 7이면 다시 데일리 3개.

## What is out of scope

- 지금 받을 이유 / 미룰 이유
- 하루에 시술 종류 여러 개, 강도 순위
- 다른 시종 추천, 또래 후기, 병원 예약 연동
- “지금 받아도 됩니다” 같은 의료 판정
- 부작용 증상 트리. 고정 한 줄만: `이상하면 시술한 병원에 연락하세요.`
- 화면에 엔진 이름, 모드 이름, `14:00` 시각 라벨

아래는 P0에서 안 만든다. **나중에** 적는다: 실제 날씨 API, 폰 푸시, 위젯, 전후 사진·점수, 날씨가 할 일을 바꾸는 것, OpenAI 호출.

## Priority for each item

### P0 — must ship

- 오늘 체크리스트가 주인공인 홈. 달력 없음
- 시술 없이 데일리 3개: `세안`, `선크림`, `보습`
- 시술 날짜 하나 넣으면 목록이 회복으로 바뀜. 모드를 고르지 않음
- P0 카테고리 **두 개:** `토닝 / 마일드 레이저`, `스킨부스터 / 주사`. 할 일 문구가 서로 다름
- 회복은 초반(N=0–2) / 후반(N=3–6) 두 상태만. 날짜마다 다른 7일 격자 없음
- `오늘 참고` (하지 말아야 할 일). 체크 불가. 종류마다 다름
- All Clear: 해야 할 일만 모두 깨면 같은 화면 배너. 스트릭 없음
- 상단 예보 mock 한 줄 (`예시`). 할 일은 바꾸지 않음
- 의료 아님 문구
- 할 일은 **로컬 템플릿**. OpenAI를 호출하지 않음. 홈이 비면 안 됨
- 체크는 그날만, 이 브라우저만 (`eunhyehyun.skin-checklist`)

### P1 — if time allows

- 나머지 네 카테고리
- 달력 뷰
- 다음 회차 예정일 + 7일 전 `다음 회차 예약을 지금 해 두세요`
- 예보 프리셋 토글 (한 줄만 바뀜)
- 오늘로 볼 날짜 컨트롤 (데모·스트릭용)
- All Clear `N일 연속` + 7일 뱃지 `피부 장벽 수호자`
- 날씨가 할 일 한 줄을 더하는 것 (모드는 같아도 됨)
- 일요일 셀카 mock 한 줄. 사진·점수 없음

### P2 — later

- 브라우저에서 OpenAI API 키를 넣어 할 일 문구를 생성. 실패하면 템플릿
- 실제 날씨·자외선·생리주기 API
- 실제 폰 푸시, 홈 화면 위젯, `14:00` 알림
- 전후 사진 비교, 피부 점수, 회복 %, 자극 지수
- All Clear 비주얼 리포트, 셀카 타임랩스
- 같은 날 여러 종류, 강도 순위

## The AI model you use, and what happens when it fails

**의도 (P2):** 브라우저 **OpenAI API**. 모델명은 키를 넣는 시점에 적는다.

**P0:** 모델을 부르지 않는다. 오늘 할 일은 아래 로컬 템플릿이다.

나중에 호출한다면 실패로 보는 것: 키 없음, 네트워크 오류, 빈 응답, `필수`/`처방`/피부 나이 숫자로 단정하는 문장.

실패하면: 같은 로컬 템플릿. 홈이 비면 안 된다. 에러 풀스크린 없음. 유저에게 `모델` / `OpenAI`라고 쓰지 않는다.

## P0 템플릿 (이 문자열이 정답)

데일리 (시술 없음 또는 N ≥ 7) — 해야 할 일만:

1. `세안`
2. `선크림`
3. `보습`

`토닝 / 마일드 레이저`

| | 해야 할 일 | 오늘 참고 (체크 불가) |
|---|---|---|
| 초반 N=0–2 | `세안`, `보습`, `선크림` | `사우나 안 가기` |
| 후반 N=3–6 | `세안`, `선크림`, `보습` | `사우나 안 가기` |

`스킨부스터 / 주사`

| | 해야 할 일 | 오늘 참고 (체크 불가) |
|---|---|---|
| 초반 N=0–2 | `세안 살살`, `보습`, `선크림 건너뛰기` | `술 안 마시기`, `사우나 안 가기` |
| 후반 N=3–6 | `세안`, `선크림`, `보습` | `술 안 마시기` |

EGF, 미세 딱지, 열감, `D+1`을 줄 문구에 쓰지 않는다.

P1 카테고리 (아직 템플릿 없음): 강한 레이저 / 박피, 보톡스 / 필러, 에너지 리프팅, 메디컬 스킨케어 / 필링.

## How you will check it works: hand tests

키 없이 한다. 네트워크 호출이 없어도 된다.

**Test 1 — 첫 화면에서 박스만 깬다**

1. 시술을 넣지 않고 홈을 연다.
2. `예시` 예보 한 줄과 `세안`·`선크림`·`보습`이 미체크. 입력 폼이 홈을 가리지 않는다.
3. `선크림`을 체크한다. 그 줄만 체크된다.
4. 통과: 10초 안에 체크할 수 있다. 빈 목록이 아니다. 참고 칸이 없다.

**Test 2 — 시술을 넣으면 목록이 그 종류로 바뀐다**

1. 어제 날짜, 이름 `리쥬란`, 카테고리 `스킨부스터 / 주사`를 저장한다.
2. 해야 할 일이 `세안 살살`, `보습`, `선크림 건너뛰기`다. (초반)
3. `오늘 참고`에 `술 안 마시기`, `사우나 안 가기`가 있다. 체크박스가 아니다.
4. 같은 날짜로 `토닝 / 마일드 레이저`를 넣으면 해야 할 일이 `세안`, `보습`, `선크림`이고 참고는 `사우나 안 가기`만이다. `술 안 마시기`가 없다.
5. 통과: 모드를 고르지 않았는데 목록이 바뀌고, 두 종류 문구가 다르다. 참고는 체크되지 않는다.

**Test 3 — All Clear는 해야 할 일만**

1. 데일리 3개를 모두 체크한다. `오늘 케어 All Clear`가 같은 화면에 보인다.
2. 시술을 넣은 뒤 해야 할 일만 체크한다. 참고를 건드리지 않아도 All Clear가 나온다.
3. 통과: 점수·카메라·연속 일수·푸시가 없다.

(P1) 예보 프리셋은 한 줄만 바꾼다. 달력·다음 회차·스트릭·셀카는 P1이라 통과 조건이 아니다.

## Rules behind the tests (P0)

- D+N: 시술일 = D+0. 오늘 = 브라우저 로컬.
- 회복 N ≤ 6. 초반 0–2, 후반 3–6. N ≥ 7이면 데일리.
- P0 카테고리 두 개. 이름에서 종류를 추측하지 않는다.
- 참고는 체크 불가. All Clear는 해야 할 일만.
- 예보 mock은 라벨만. 할 일 배열을 바꾸지 않는다.
- `경고` / `필수` / `처방` / EGF / 딱지 / 열감으로 쓰지 않는다.
