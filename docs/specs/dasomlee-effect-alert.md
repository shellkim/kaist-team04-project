# Feature Spec — 효과 감소 시점 알림

Author: 이다솜 (dasomlee)
Date: 2026-10-29
Status: decided (v0.1, 조별과제 프로토타입 기준)

한 줄: 보톡스·필러를 받은 날짜를 남기면, 일반적으로 효과가 줄어들기 시작하는 시점에 "지금 효과가 어떻게 느껴지나요?"라고 묻고, 내가 감소를 느낀 시점을 기록해 다음 시술 시점을 내가 판단할 수 있게 해주는 알림.

- WhyTree 참조: `docs/whytree/dasomlee.md`, 노드 **다음 시술 시점 판단** → 나에게 맞는 시술 계획 → 내가 만족하는 피부 상태를 오래 유지하기
- 우선순위: **P0** 반드시 만든다 / **P1** 시간이 되면 / **P2** 나중에

**원칙: 판단 재료를 줄 뿐, 재시술을 권하지 않는다.** 알림·카드 어디에도 "예약하세요", "받으세요", "다시 받아보세요"가 없다. 결정은 사용자가 한다. 우리 앱이 또 하나의 "병원 권유"가 되면 형제 노드 "타인의 의견에 휘둘리지 않는 결정"을 해친다.

---

## 1. 누구를 위한 것이고, 문제는 언제 드러나는가

**사용자**: 시술 회당 30~50만 원 이상을 쓸 수 있지만 병원의 패키지 권유와 과잉 시술은 경계하는 20~40대 워킹우먼. 보톡스나 필러를 주기적으로 받는다. 1번 사용자는 다솜 본인.

**문제가 드러나는 순간**

| 순간 | 무슨 일이 일어나나 |
|---|---|
| 시술 3~6개월 후, 거울을 보다가 | "효과가 좀 빠진 것 같은데?" 싶지만 언제 받았는지 정확히 기억나지 않는다 |
| 병원에서 연락이 오거나 이벤트 문자를 받았을 때 | 지금 다시 받을 때인지, 병원이 팔고 싶은 건지 구분할 근거가 없다 |
| 다음 시술을 고민할 때 | 지난번엔 몇 달 만에 효과가 줄었는지 남아 있지 않아 매번 처음부터 상담에 의존한다 |

**사용자가 원하는 상태**: "내 기준으로 판단했다"는 확신. 다음 시술 시점을 병원의 권유가 아니라 내 경과와 내 체감으로 정한다.

## 2. 사용자가 할 수 있는 일 (단계별)

| # | 단계 | 사용자가 하는 일 | 시스템이 하는 일 | 우선순위 |
|---|---|---|---|---|
| 1 | 시술 기록 | 시술 종류(드롭다운: 보톡스 / 필러(히알루론산) / 기타)와 시술 날짜를 넣는다 | 날짜는 정확한 날짜만 받는다. 미래 날짜는 막는다. "기타"를 고르면 "아직 지원하지 않아요"를 보여주고 저장하지 않는다 | P0 |
| 2 | 기록 목록 | 저장된 시술과 상태(추적 중 / 감소 체감 / 범위 지남 / 새 시술로 대체)를 본다 | 같은 종류에서 시술일이 더 늦은 기록(상태 무관)이 있으면, 추적 중인 기록은 알림이 끝나고 상태가 "새 시술로 대체"가 된다. 그래서 예전 날짜를 나중에 입력하면 그 기록이 대체되고, 최신 기록은 그대로 추적된다. 같은 종류·같은 날짜는 "이미 기록된 시술이에요"로 막는다 (여러 부위도 기록 하나) | P0 |
| 3 | 기록 삭제 | 잘못 넣은 기록을 지운다 | 알림도 함께 사라진다 | P0 |
| 4 | 기록 수정 | 날짜나 종류를 고친다 | 알림 일정을 다시 계산한다 | P1 |
| 5 | 날짜 시뮬레이터 | 화면 상단의 "오늘 날짜"를 앞으로 옮긴다. "실제 오늘로" 버튼으로 되돌린다 | 알림함을 그 날짜 기준으로 다시 계산한다 | P0 |
| 6 | 알림 받기 | 알림함에서 셀프 체크 알림을 본다 (§2.1 문구) | 지속 기간표(§2.2)와 일정 규칙(§2.3)으로 알림을 만든다 | P0 |
| 7 | 셀프 체크 | "아직 남아 있어요" / "줄어든 것 같아요" / "잘 모르겠어요" 중 하나를 누른다 | §2.3의 분기를 따른다 | P0 |
| 8 | 기록 카드 | "줄어든 것 같아요"를 누른 뒤 기록 카드를 본다 | 시술 종류, 시술일, **N주째에 효과 감소를 느꼈어요**, 일반 범위를 보여준다. 버튼은 "새 시술 기록하기" 하나뿐이다 | P0 |
| 9 | 실제 푸시 알림 | 앱을 열지 않아도 알림을 받는다 | 웹 푸시 또는 앱 푸시 | P1 |
| 10 | 사진으로 확인 | "잘 모르겠어요"를 누르면 시술 직후 사진과 지금 사진을 나란히 본다 | 씨앗 "시술 전후 사진 비교"와 [새 방법] "촬영 조건 가이드"에 연결 | P1 |
| 11 | 부위별 범위 | 시술 부위(미간·사각턱, 입술·볼 등)를 함께 넣는다 | 부위별 지속 기간표를 쓴다 | P1 |
| 12 | 지원 시술 확대 | 스킨부스터(리쥬란 등), 리프팅(울쎄라·슈링크)도 기록한다 | 효과 체감의 개인차가 커서 별도 규칙이 필요 | P1 |
| 13 | 시술 이력 연동 | 소라님의 AI 대화 기반 시술 이력에서 기록을 불러온다 | 날짜가 모호한 기록("2025년 여름")만 정확한 날짜를 다시 묻는다 | P1 |
| 14 | 나의 주기 | 같은 시술을 여러 번 기록하면 "당신은 보통 14주쯤 감소를 느껴요"를 본다 | 쌓인 감소 체감 시점으로 첫 체크 시점을 개인화한다 | P2 |

### 2.1 고정 문구 템플릿

모든 문구는 템플릿으로 고정한다. LLM이 생성하지 않는다.

- **셀프 체크 알림**: "{시술} 받은 지 {N}주째예요. 일반적으로 {범위} 사이에 효과가 줄어들기 시작해요. 지금 효과가 어떻게 느껴지나요?"
- **범위 지남 안내**: "{시술} 받은 지 {N}주째예요. 일반적인 지속 기간({범위})을 지났어요. 이 시술의 알림은 여기서 마칠게요."
- **기록 카드**: "{시술} · {시술일} 시술 · {N}주째에 효과 감소를 느꼈어요 (일반 범위: {범위})"
- **면책 문구** (알림 상세와 기록 카드 하단에 고정): "일반적인 지속 기간을 바탕으로 한 안내이며 의학적 판단이 아니에요. 이상 증상이 있다면 시술받은 병원에 문의하세요."

{N}은 `floor((오늘 − 시술일) / 7일)`이다.

### 2.2 지속 기간표 (P0)

부위는 나누지 않는다. 알림이 일찍 오는 건 해가 없지만(사용자가 "아직 남아 있어요"라고 답하면 된다) 늦게 오는 건 쓸모가 없으므로, 첫 체크는 범위의 **하한**에서 보낸다.

| 시술 | 일반 범위 | 첫 체크 (하한) | 재체크 간격 | 상한 | 근거 |
|---|---|---|---|---|---|
| 보톡스 | 3~4개월 | 12주 | 2주 | 16주 | 안면 미용 보톡스 지속 기간 리뷰: 여성 3~5개월 ([PubMed 20369902](https://pubmed.ncbi.nlm.nih.gov/20369902/)), 피부과 전문의 평균 3.5~4개월 |
| 필러 (히알루론산) | 6~12개월 | 26주 | 4주 | 52주 | FDA 소비자 안내: 히알루론산 필러 약 6~12개월 ([FDA Wrinkle Fillers](https://www.fda.gov/MedicalDevices/ProductsandMedicalProcedures/CosmeticDevices/WrinkleFillers/ucm227749.htm)). 이 URL은 예전 버전이라 최신 FDA 페이지와 대조가 필요하다 |

비히알루론산 필러(스컬트라 등)는 "기타"로 처리하며 지원하지 않는다.

### 2.3 알림 일정 규칙

한 기록에는 **열린 알림이 최대 하나**만 있다. 응답하지 않은 알림은 그대로 남고, 그 위에 새 알림이 쌓이지 않는다. 알림은 저장하지 않고, 기록 + 응답 + 오늘 날짜로 매번 계산한다.

1. 다음 체크일 = (응답이 없으면) 시술일 + 첫 체크, (응답이 있으면) 마지막 응답일 + 재체크 간격
2. 다음 체크일이 시술일 + 상한을 넘거나, 알림을 띄우는 오늘이 이미 시술일 + 상한을 넘었으면, 셀프 체크 대신 **범위 지남 안내**를 띄운다. 상한 당일(보톡스 16주 = 112일째)까지는 셀프 체크다. 범위 지남 안내에는 "확인했어요" 버튼 하나만 있고, 누르면 알림함에서 사라지며 그 기록의 알림이 끝난다 (상태: 범위 지남). 확인 전에도 기록 목록에는 "범위 지남"으로 보인다
3. 오늘 ≥ 다음 체크일이면 알림을 띄운다. 놓친 체크를 여러 개 몰아서 띄우지 않고, 하나만 띄운다. 응답일·감소 체감 주차는 시뮬레이터의 오늘 날짜 기준이다
4. 셀프 체크 응답:
   - **아직 남아 있어요** → 응답일을 기록하고 1번으로 돌아간다
   - **줄어든 것 같아요** → 응답일 기준 N주를 감소 체감 시점으로 기록하고, 기록 카드를 보여준 뒤 알림을 끝낸다 (상태: 감소 체감)
   - **잘 모르겠어요** → P0에서는 "아직 남아 있어요"와 같다 (P1에서 사진 비교로 연결)

**입력 날짜 엣지 케이스**
- 미래 날짜는 입력할 수 없다 (기준은 시뮬레이터의 오늘 날짜).
- 입력한 날짜가 이미 첫 체크 시점을 지났다면, 오늘 날짜로 셀프 체크 알림을 바로 하나 만든다.
- 입력한 날짜가 이미 상한도 지났다면, 범위 지남 안내를 바로 띄우고 끝낸다.

예시 (보톡스, 2026-07-01 시술, 매번 "아직 남아 있어요"): 09-23(12주) → 10-07(14주) → 10-21(16주) → 11-04(18주, 상한 16주를 넘으므로 범위 지남 안내).

### 2.4 데이터 구조 (P0)

필드 이름은 소라님 Spec(`docs/specs/sorakim-treatment-log.md` §6)의 `record_id`, `treatment_name`, `treatment_date`, `created_at`과 맞춘다. 단, `treatment_date`는 ISO 날짜(`YYYY-MM-DD`)만 받는다. 프로토타입끼리 localStorage를 공유하지 않으므로 키는 따로 쓴다.

```json
{
  "record_id": "record_20261029_001",
  "treatment_name": "보톡스",
  "treatment_date": "2026-07-01",
  "created_at": "2026-10-29T10:30:00Z",
  "status": "tracking",
  "check_responses": [
    { "date": "2026-09-23", "answer": "remaining" },
    { "date": "2026-10-07", "answer": "declined" }
  ],
  "felt_decline_week": 14
}
```

- `status`: `tracking` | `felt_decline` | `past_range` | `replaced`. `past_range`는 범위 지남 안내에서 "확인했어요"를 눌렀을 때 저장한다. 그 전에는 `tracking`으로 저장된 채 화면에서만 범위 지남으로 계산해 보여준다
- `answer`: `remaining` | `declined` | `unsure`
- 저장소: localStorage `effect_alert_records`(배열), `effect_alert_today`(시뮬레이터 날짜, 없으면 실제 오늘)

## 3. 어느 WhyTree 노드를 섬기는가

| 기능 | 섬기는 노드 |
|---|---|
| 시술 기록, 기록 목록 | 씨앗 **시술 이력 기록** → 다음 시술 시점 판단 |
| 셀프 체크 알림, 범위 지남 안내 | [새 방법] **효과 감소 시점 알림** → **다음 시술 시점 판단** |
| 기록 카드 (감소 체감 시점) | **다음 시술 시점 판단** → 나에게 맞는 시술 계획 |
| 재시술 권유 금지 원칙 | **타인의 의견에 휘둘리지 않는 결정** (형제 노드를 해치지 않기) |

| 전체 | 뿌리: **내가 만족하는 피부 상태를 오래 유지하기** |

## 4. 범위 밖

- 재시술 권유, 예약, 병원 연결, 병원 추천, 가격 비교
- 의료 조언·진단 (효과가 "줄었다"고 판정하지 않고, 사용자의 체감만 기록한다)
- AI 사진 분석으로 효과 감소 판정 (P1 이후의 별도 결정이며, PROJECT.md의 중단 조건 "AI 시각 분석 신뢰"를 먼저 검증해야 한다)
- 보톡스·필러(히알루론산) 외 시술의 알림 (P0)
- 시술 부위별 지속 기간 (P0)
- 다른 사용자와 비교하는 통계 (씨앗 "또래 시술 현황"은 별도 기능)
- 실제 푸시 알림, 서버 저장, 로그인 (P0)

## 5. AI 모델과 실패 시 동작

**P0: 모델 없음.** 알림 시점은 지속 기간표와 일정 규칙으로 정해지고, 셀프 체크는 버튼이다. LLM이 꼭 필요한 곳이 없다. 알림 문구를 LLM이 만들게 하면 "다시 받아보세요" 같은 권유 문장이 섞일 수 있어, 고정 템플릿(§2.1)으로 원칙을 보장한다.

| 용도 | 모델 | 입력 | 실패 시 |
|---|---|---|---|
| 알림 시점 계산 (P0) | 모델 없음. 규칙(§2.2, §2.3) | 시술 종류, 시술일, 응답 기록, 오늘 날짜 | 해당 없음 (결정적 계산) |
| 알림 문구 (P0) | 모델 없음. 고정 템플릿(§2.1) | 시술 종류, N주, 범위 | 해당 없음 |
| 저장 (P0) | — | localStorage | 저장 실패 시 "저장하지 못했어요. 다시 시도해 주세요"와 재시도 버튼. 입력값은 폼에 남긴다 |
| 사진으로 확인 (P1) | 미정. 촬영 조건 가이드가 먼저 있어야 함 | 시술 직후 사진, 지금 사진 | 분석 실패나 촬영 조건 불일치 시 사진을 나란히만 보여주고 판단은 셀프 체크로 받는다 |
| 나의 주기 (P2) | 규칙 또는 간단한 통계. LLM 아님 | 같은 시술의 `felt_decline_week` 기록 | 감소 체감 기록이 2개 미만이면 개인화하지 않고 §2.2의 하한을 쓴다 |

## 6. 손으로 확인하는 검사

1. **일정 규칙이 맞는가** — 보톡스를 2026-07-01로 기록한다. 시뮬레이터를 09-22로 두면 알림이 없고, 09-23으로 옮기면 "12주째" 셀프 체크가 하나 생기는지 확인한다. "아직 남아 있어요"를 누르고 10-07로 옮기면 "14주째" 알림이 다시 생기는지, "줄어든 것 같아요"를 누르면 기록 카드에 "14주째에 효과 감소를 느꼈어요"가 나오고 이후 날짜를 2027년까지 넘겨도 그 기록의 알림이 다시 생기지 않는지 확인한다.
2. **엣지 케이스를 막는가** — 실제 오늘(2026-10-29) 기준으로 ① 내일 날짜를 넣으면 저장이 막히고, ② 필러를 2025-01-10으로 넣으면 셀프 체크 버튼 없이 범위 지남 안내가 바로 하나만 뜨고, ③ "기타"를 고르면 "아직 지원하지 않아요"가 뜨고 저장되지 않는지 확인한다.
3. **선을 넘지 않는가** — 셀프 체크 알림, 범위 지남 안내, 기록 카드를 각각 한 번씩 띄운 뒤 화면의 모든 문장을 읽는다. "예약", "받으세요", "받아보세요", "다시 시술", "추천"이 하나도 없고, 알림 상세와 기록 카드 하단에 면책 문구가 있는지 확인한다.
