**작성자**: sorakim

**기능명**: AI 대화 기반 시술 이력 기록  
**연결 WhyTree**: 과거 시술 경험의 체계적인 축적 → AI 대화 기반 시술 이력 기록

---

## 1. 개요

사용자가 AI와 자연스러운 자연어 대화를 통해 과거의 피부 미용 시술 경험을 기록합니다. AI는 대화 내용에서 시술 정보를 추출하고 사용자가 이를 검토·수정한 후 저장합니다. 대화의 맥락을 보존하기 위해 대화 원문과 구조화된 시술 이력을 함께 관리합니다.

---

## 2. Target User

- **Primary**: 자신의 피부 시술 경험을 체계적으로 기록하고 관리하려는 사용자
- **Context**: 과거에 여러 시술을 받았지만 정확한 기록이 없거나, 시술별 효과/만족도를 추적하고 싶은 사용자

---

## 3. Problem Moment

- 사용자가 이전 시술 경험을 떠올릴 때: "정확히 언제 어떤 시술을 받았더라?"
- 여러 시술을 이야기할 때: 시술명, 시기, 비용, 만족도 등을 일일이 입력하기 번거로움
- 의료진 상담 전: 자신의 시술 이력을 체계적으로 정리하고 싶음

---

## 4. 기본 기능

### 4.1 AI 대화 기반 정보 추출

**사용자 행동**:
- 사용자가 AI와 자연어로 과거 피부 시술 경험을 자유롭게 이야기합니다.
- 예: "2025년 여름에 보톡스 맞고, 작년 초에는 필러 시술도 했어. 효과는 좋았는데 비용이 좀..."

**AI 역할**:
- 대화 내용에서 시술별로 다음 정보를 추출합니다:
  - **필수 항목**: 시술명, 시술 시기
  - **선택 항목**: 비용, 통증 수준, 효과, 만족도
- AI는 불확실한 정보를 추측해서 채우지 않습니다. 미입력 상태로 유지합니다.
- 한 번의 대화에서 **여러 시술을 독립적인 기록으로 구분**합니다.

### 4.2 필드 정의

| 필드 | 필수/선택 | 입력 형식 | 설명 |
|------|---------|---------|------|
| 시술명 | 필수 | 텍스트 | 보톡스, 필러, 레이저, 리프팅 등 |
| 시술 시기 | 필수 | 텍스트 | 정확한 날짜 또는 "2025년 여름", "작년 초" 수준 |
| 비용 | 선택 | 숫자 (원) | 시술 비용 |
| 통증 수준 | 선택 | 수치 (1-10) 또는 텍스트 | 시술 중 통증 정도 |
| 효과 | 선택 | 텍스트 | 시술의 효과 (예: "주름 개선", "피부 톤 밝아짐") |
| 만족도 | 선택 | 수치 (1-5점) 또는 텍스트 | 시술 만족도 |

### 4.3 AI 추출 실패 시 처리 (재질문 + 수동 입력)

**필수 항목(시술명 또는 시술 시기)을 못 찾은 경우**:
1. AI가 누락된 정보만 사용자에게 재질문합니다.
   - 예: "죄송합니다. 어떤 종류의 시술이었나요?"
2. 이미 확인된 정보는 반복해서 묻지 않습니다.
3. 재질문 응답 처리:
   - 사용자가 실제 정보를 제공한 경우 (예: "보톡스였어") → 해당 필드 업데이트
   - 사용자가 정보를 모른다고 응답한 경우 (예: "기억나지 않아", "모르겠어", "잘 모르겠어") → 해당 필드는 미입력 상태로 유지
   - 다른 필드값은 유지 (예: 시술 시기나 비용은 유지)
4. 재질문으로도 정보를 확보하지 못하면, 사용자는 검토 화면에서 직접 입력하거나 해당 기록을 제외할 수 있습니다.
5. 필수 항목이 미입력인 기록은 최종 저장 시 차단됩니다.

### 4.4 추출 결과 검토 및 수정

**UI 형식**: 테이블 (행: 개별 시술, 열: 필드)

- 추출된 모든 시술을 하나의 테이블로 표시합니다.
- 각 행에 "수정" 버튼이 있어 클릭 시 행별 수정 폼이 나타납니다.
- 수정 폼:
  - 기존 추출값이 미리 입력되어 있습니다.
  - 사용자가 각 항목을 수정할 수 있습니다.
  - 필수 항목(시술명, 시술 시기) 누락 검증을 수행합니다.
  - "저장" 및 "취소" 버튼을 제공합니다.
- 선택 항목이 미입력이면 빈 상태로 표시합니다.
- 셀 직접 편집 기능은 P1에서 추가합니다.

### 4.5 부분 저장 (체크박스)

- 테이블의 각 행 시작에 체크박스를 제공합니다.
- 사용자는 저장할 시술만 선택할 수 있습니다.
- 선택하지 않은 시술은 이번 저장에서 제외됩니다.
- 선택하지 않은 시술의 정보는 저장 완료 후 폐기됩니다.

### 4.6 P0에서의 데이터 관리

**대화 원문**:
- P0에서는 대화 원문을 영구 저장하지 않습니다.
- 임시 메모리에만 유지되며, 새로운 대화 시작 시 폐기됩니다.
- P1에서 대화 원문 보관 기능을 추가할 예정입니다.

**저장된 시술 이력**:
- 구조화된 시술 데이터(시술명, 시술 시기 등)만 localStorage에 저장합니다.
- 각 기록은 고유 ID를 가지고 독립적으로 관리됩니다.

**저장 완료 후**:
- 새로운 대화 세션이 시작됩니다 (이전 대화와 분리).
- P1에서 같은 대화 이어가기 기능을 추가할 예정입니다.

## 5. P0 사용자 흐름

```
1. 대화 시작
   ↓
2. 사용자가 시술 경험 이야기
   ↓
3. AI가 정보 추출 (OpenAI API 호출)
   ├─ API 오류 → 오류 메시지 + "다시 시도" 버튼
   └─ 성공 → 다음 단계
   ↓
4. 필수 항목 검증
   ├─ 시술명 또는 시술 시기 누락 → 재질문 (또는 수동 입력 안내)
   └─ 필수 항목 있음 → 다음 단계
   ↓
5. 추출 결과를 테이블로 표시
   ↓
6. 필요시 각 시술의 "수정" 버튼으로 수정 (행별 폼)
   ├─ 필수 항목 검증 (수정 폼에서)
   └─ "저장" 또는 "취소"
   ↓
7. 저장할 시술에 체크박스 선택
   ↓
8. 저장 실행
   ├─ 저장 오류 → 오류 메시지 + 재시도 안내
   └─ 저장 성공 → 다음 단계
   ↓
9. 저장 완료 + 대화 종료

** P1에서 추가될 기능 **
- 대화 원문 보관 동의 및 저장
- 저장 완료 후 같은 대화에서 추가 기록
- 저장된 기록 재수정 및 삭제
```

**P0 주의사항**:
- 대화 원문은 이번 저장 사이클에서 영구 저장되지 않습니다. (임시 메모리에만 유지)
- 저장 완료 후 대화를 종료하면 새로운 대화 세션이 시작됩니다.
- 저장된 기록의 재수정 및 삭제는 P1에서 구현합니다.

## 6. 데이터 구조 (P0)

### 6.1 localStorage에 저장되는 데이터

**시술 이력** (treatment_record) - P0에서 저장

```json
{
  "record_id": "record_20261028_001",
  "treatment_name": "보톡스",
  "treatment_date": "2025년 여름",
  "cost": null,
  "pain_level": null,
  "effect": "주름 개선",
  "satisfaction": null,
  "created_at": "2026-10-28T10:30:00Z"
}
```

**저장소**:
- localStorage의 "treatment_records" 키에 배열로 저장
- 각 브라우저/디바이스마다 독립적으로 저장됨
- 브라우저 캐시 삭제 시 데이터 소실됨

### 6.2 메모리에만 유지되는 데이터 (P0)

**현재 대화 세션** (임시):
- 사용자 입력 텍스트
- AI 응답 (JSON)
- 추출된 시술 목록 (임시)

**영구 저장되지 않음**:
- 대화 원문
- 사용자-AI 상호작용 로그

### 6.3 P1에서 추가될 데이터 구조

**대화 세션** (P1):
- session_id: 고유 ID
- conversation_text: 전체 대화 원문
- created_at: 생성 시간

**시술 이력 참조** (P1):
- 각 시술 이력이 session_id를 참조하는 구조

## 7. AI 모델 및 실패 시 대체 흐름

### 7.1 AI 모델 선택 (P0)

**선택**: OpenAI API의 gpt-4o-mini
- 이유: 비용 효율적이며 자연어 정보 추출과 구조화된 JSON 응답에 적합함
- 프롬프트는 JSON 구조화 추출에 최적화하여 설계
- P0에서는 파인튜닝 불필요 (프롬프트 엔지니어링으로 충분)

**API 키 관리** (필수):
- `.env` 파일에 `OPENAI_API_KEY` 저장 (서버 측)
- 브라우저에 직접 노출 금지
- Git에 `.env` 파일 커밋 금지 (`.gitignore` 추가)

### 7.2 AI 응답 JSON 스키마

```json
{
  "success": true,
  "treatments": [
    {
      "treatment_name": "보톡스",
      "treatment_date": "2025년 여름",
      "cost": null,
      "pain_level": null,
      "effect": "주름 개선",
      "satisfaction": null,
      "extracted_from_text": "2025년 여름에 보톡스 맞고..."
    },
    {
      "treatment_name": null,
      "treatment_date": "작년 초",
      "cost": 500000,
      "pain_level": "중간",
      "effect": null,
      "satisfaction": 4,
      "extracted_from_text": "작년 초에는 필러 시술했어..."
    }
  ],
  "missing_required": [
    {
      "index": 1,
      "field": "treatment_name",
      "message": "어떤 종류의 시술이었나요?"
    }
  ]
}
```

### 7.3 실패 시 대체 흐름

**상황 1: AI가 필수 항목을 추출하지 못함** (success: true이지만 missing_required 있음)
1. AI의 `missing_required` 배열에서 누락된 필드 확인
2. 각 시술별로 누락된 정보만 재질문
   - 예: "두 번째 시술의 이름이 뭐였나요?"
3. 사용자 답변 → 수동으로 해당 필드 업데이트
4. 재질문으로도 못 찾으면 사용자가 검토 테이블에서 직접 입력

**상황 2: OpenAI API 호출 실패** (success: false 또는 네트워크 오류)
1. 오류 메시지: "AI 서버 연결 실패. 잠시 후 다시 시도해 주세요."
2. "다시 시도" 버튼 표시
3. 사용자의 입력 내용은 임시 저장 (새로고침 시 소실)
4. 최대 3회 재시도 후 안내: "계속 실패하면 아래 정보를 직접 입력하세요"

**상황 3: localStorage 저장 실패** (드물지만 발생 가능)
1. 오류 메시지: "데이터 저장 실패. 입력하신 내용을 다시 확인해 주세요."
2. "다시 저장" 버튼
3. 브라우저 저장소 부족 시: "브라우저 저장소가 가득 찼습니다. 기존 기록 중 일부를 삭제하세요."

**상황 4: 사용자 입력 오류** (필수 항목 누락, 과도한 길이)
1. 필수 항목 누락: "시술명과 시술 시기는 필수입니다"
2. 과도한 입력: "입력 길이가 너무 깁니다. (최대 500자)"
3. 오류 필드는 빨간색으로 표시
4. "확인" 후 수정 폼에서 다시 입력

## 8. 우선순위 및 범위

### P0 (필수 구현) - 핵심 검증 대상

**목표**: AI와 자연어로 대화한 내용을 구조화된 시술 이력으로 전환할 수 있는가?

**포함된 기능**:
1. **AI 대화 기반 정보 추출** (OpenAI API 호출)
   - 자연어 입력에서 시술명, 시술 시기 추출
   - 선택 항목(비용, 통증, 효과, 만족도) 추출 시도
2. **재질문 로직** (필수 항목 누락 시)
   - 시술명 또는 시술 시기가 빈 경우 AI가 재질문
   - 누락된 정보만 질문 (기존 정보 반복 없음)
3. **추출 결과 테이블** (읽기 전용)
   - 시술별로 행 표시
   - 각 필드 표시 (필수 및 선택)
4. **행별 수정 폼**
   - "수정" 버튼 클릭 시 폼 오픈
   - 기존 값 미리 표시
   - 필드 편집 가능
5. **필드 검증**
   - 필수 항목(시술명, 시술 시기) 누락 검사
   - 수정 폼에서 저장 전 검증
6. **선택적 부분 저장** (체크박스)
   - 저장할 시술 선택
   - 선택한 시술만 localStorage에 저장
7. **저장된 시술 이력 조회**
   - 저장된 기록 목록 조회
   - 개별 기록 확인
8. **기본 예외 처리**
   - OpenAI API 오류: 오류 메시지 + "다시 시도" 버튼
   - 입력 오류: 필수 항목 누락 알림
   - 저장 오류: 오류 메시지 + 재시도 안내

**P0 제약사항**:
- 대화 원문은 임시 메모리에만 유지되며, 영구 저장되지 않습니다.
- 저장 완료 후 새로운 대화 세션이 시작됩니다 (이전 대화와 분리).
- 저장된 기록의 재수정 및 삭제 기능은 없습니다.

**기술 스택** (P0 구현):
- **AI**: OpenAI API (gpt-4o-mini)
- **프론트엔드**: HTML / CSS / JavaScript (단일 페이지)
- **백엔드**: Node.js 최소 API 서버 (API 키 관리)
- **저장소**: 브라우저 localStorage (세션당 최대 일부 기록)
- **데이터 형식**: JSON

### P1 (우선순위 높음)

- [ ] 대화 원문 영구 저장 및 세션 관리
- [ ] 저장된 시술 이력 재수정 (개별 기록 수정)
- [ ] 저장된 시술 이력 삭제 (부분 및 전체)
- [ ] 저장 완료 후 같은 대화에서 추가 시술 기록
- [ ] 중복 판단 불확실 시 AI가 사용자에게 추가 질문
- [ ] 셀 직접 편집 기능 (테이블에서 바로 수정)
- [ ] 저장된 대화 원문 조회 및 검색
- [ ] 세션 재개/히스토리 조회
- [ ] 여러 시술 대량 추출 처리 (입력량 제한 + 안내)

### P2 (장기 계획)

- [ ] 과거 대화 재분석을 통한 데이터 보완
- [ ] 수정 이력 추적
- [ ] AI 대화를 통한 기존 기록 수정
- [ ] 시술별 트렌드 분석 (예: 가장 최근 시술, 만족도 높은 시술)
- [ ] 의료진 상담용 질문 목록 자동 생성

## 9. Out of Scope (P0)

**기능 제외**:
- 사용자 계정 관리 (로그인, 회원가입)
- 대화 원문의 영구 저장 및 조회
- 저장된 기록의 재수정 및 삭제
- 저장 완료 후 같은 대화 이어가기
- 세션 재개/히스토리 기능
- 의료 기록 동기화 (진료 내역, 영수증 등)
- 다른 플랫폼과의 동기화
- 고급 검색/필터링
- 모바일 앱 (웹 기준)
- 음성 입력
- 이미지 업로드

**기술 제약**:
- P0에서는 localStorage만 사용 (서버 저장소 미사용)
- 대화 기록은 브라우저 메모리에만 유지 (세션 종료 시 소실)
- 실시간 협업 편집 미지원
- API 키 클라이언트 측 관리 금지 (보안)

## 10. 수동 테스트 시나리오 (P0 기준)

### 시나리오 1: 여러 시술을 한 번에 기록하고 일부만 저장

**전제**:
- 사용자: "2025년 여름에 보톡스 맞고, 작년 초에는 필러 시술했어."
- 기대: AI가 2개 시술을 추출 → 테이블에서 1개만 선택해서 저장

**테스트 단계**:
1. 사용자가 입력을 제출하면 OpenAI API가 호출되는가?
2. API 응답이 정상적으로 파싱되는가? (JSON 형식)
3. 테이블에 2행이 표시되는가? (보톡스, 필러)
4. 각 행의 필드(시술명, 시술 시기)가 정확하게 표시되는가?
5. 체크박스를 통해 보톡스만 선택할 수 있는가?
6. "저장" 버튼 클릭 시 선택된 1개 기록만 localStorage에 저장되는가?
7. 저장 완료 후 "저장 완료" 메시지가 표시되는가?
8. 저장된 기록 목록에서 보톡스 1개만 조회되는가?

**성공 기준**:
- 부분 저장이 정상 작동하고, 선택된 기록만 저장됨

---

### 시나리오 2: 필수 항목 재질문 후 수동 입력

**전제**:
- 사용자: "작년에 어떤 피부 시술을 받았는데... 이름이 뭐였더라. 효과는 정말 좋았어."
- 기대: AI가 시술명 미입력 → 재질문 → 사용자가 명확하게 답하거나, 테이블에서 직접 입력

**테스트 단계**:
1. AI 응답에서 `missing_required` 배열에 시술명이 있는가?
2. 화면에 "어떤 시술이었나요?"라는 재질문 메시지가 표시되는가?
3. 사용자가 "필러였어" 답했을 때 이 정보가 테이블에 반영되는가?
4. 만약 사용자가 재질문에 답하지 않으면 테이블의 시술명이 공백인가?
5. 공백인 필드에서 "수정" 버튼을 클릭하면 수정 폼이 열리는가?
6. 수정 폼에서 시술명을 입력할 수 있는가?
7. 필수 항목(시술명, 시술 시기) 모두 입력되지 않으면 "필수 항목입니다" 경고가 나는가?
8. 필수 항목을 입력한 후 저장 가능한가?

**성공 기준**:
- 재질문과 수동 입력 플로우가 모두 작동하며, 필수 항목 검증이 동작함

---

### 시나리오 3: API 오류 처리

**전제**:
- OpenAI API가 일시적으로 사용 불가능한 상황 (예: API 키 오류, 네트워크 오류)
- 사용자: "2026년 초에 레이저 시술 받았어."

**테스트 단계**:
1. API 호출이 실패하는가?
2. 오류 메시지가 사용자 화면에 표시되는가? (예: "AI 서버 연결 실패")
3. "다시 시도" 버튼이 표시되는가?
4. "다시 시도" 버튼 클릭 시 같은 입력으로 재시도되는가?
5. API가 복구되면 정상 작동하는가?
6. 최대 재시도 후 수동 입력 안내가 표시되는가?

**성공 기준**:
- API 오류가 적절하게 처리되고, 사용자에게 명확한 피드백이 제공됨

**상위 노드**: 과거 시술 경험의 체계적인 축적

**같은 레벨의 다른 수단**:
- 진료 내역·영수증 기반 자동 기록 [대안]

**상위 계층**: 개인 시술 경험의 활용 (Level 2)  
**최상위**: 피부 미용에 대한 주체적인 의사결정 (Level 1)

## 12. API 키 및 보안 관리

**중요**: 이 기능은 OpenAI API를 호출합니다. 다음을 반드시 준수하세요:

1. **API 키 보호**
   - OpenAI API 키는 `.env` 파일에 저장 (서버 측)
   - 브라우저 JavaScript에 직접 노출 금지
   - Git에 `.env` 파일 커밋 금지 (`.gitignore` 추가)

2. **API 호출**
   - Node.js 백엔드 서버를 통해서만 호출
   - 프론트엔드 → 백엔드 → OpenAI API (체인 구조)
   - 최대 3회 재시도 로직

3. **테스트 데이터**
   - P0 구현 시 실제 의료 기록 사용 금지
   - 가상의 피부 시술 데이터로만 테스트
