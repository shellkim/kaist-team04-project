# Feature Spec — Year Pacemaker (내 1년을 설계해주는 언니)

Author: solbi kim (김솔비)
Date: 2026-10-29
Status: decided (v0.1, 조별과제 프로토타입 기준)

한 줄: 내 사진을 폰 안에서만 읽어 강점을 찾고, 내가 고른 모습으로 나이 들기 위해 예산 안에서 꼭 필요한 루틴을 짜고, 생리주기에 맞춰 때 되면 불러주는 1년짜리 언니.

- WhyTree 참조: `docs/whytree/solbi.kim.md`, 뿌리 "아름답게 나이 들기 — 고유의 분위기와 이지적임을 유지하며 관리"
- 우선순위: **P0** 반드시 만든다 / **P1** 시간이 되면 / **P2** 나중에

---

## 1. 누구를 위한 것이고, 문제는 언제 드러나는가

**사용자**: 자기 일에 열심이고 자신에게 투자하는 경제력 있는 30대 여성. 피부과 시술 경험이 있고, 바빠서 관리의 관심 편차가 크다. 1번 사용자는 solbi 본인.

**문제가 드러나는 순간**

| 순간 | 무슨 일이 일어나나 |
|---|---|
| 바쁜 몇 달이 지나고 거울을 본다 | "아차, 나 늙었네." 방치했다는 자각과 불안 |
| 인스타 뷰티 피드를 본다 | 여러 사람의 조각이 한 사람이 다 해야 하는 기준처럼 쇄도해 급해진다 |
| 시술을 결정해야 한다 | 공신력 없는 카더라, 병원마다 다른 말, 할부·적립금이 뒤섞인 예산 |
| 연말에 돌아본다 | 얼마 썼는지 모른다. 머릿속 플랜만 있고 궤적이 없다 |

**사용자가 원하는 상태**: "나답게 잘 관리되고 있다"는 확신. 비교가 아니라 자기 기준에서 오는 안심.

## 2. 사용자가 할 수 있는 일 (단계별)

### 첫날

| # | 단계 | 사용자가 하는 일 | 시스템이 하는 일 | 우선순위 |
|---|---|---|---|---|
| 1 | 사진 읽기 | 폰의 사진 중 정면 민낯 사진 3~5장을 고른다 | 기기 안에서만 읽는다. 업로드 없음 | P0 |
| 2 | 강점 3개 | 언니가 찾아낸 고유의 강점 3개를 본다 | 결점이 아니라 지킬 것을 말한다 (예: 또렷한 눈매, 광대 라인, 피부 결) | P0 |
| 3 | 지킬 것 고르기 | 3개 중 "나이 들어도 꼭 남기고 싶은 것"을 1~2개 고른다 | 선택을 추구미의 제약으로 저장 | P0 |
| 4 | 분위기 어휘 | 어휘 카드(이지적·단정한·온화한·또렷한·우아한·활기찬 …) 중 2~3개를 고른다 | 사람 레퍼런스는 제공하지 않는다 | P0 |
| 5 | 두 장의 미래 | 10년 뒤 **자연 노화의 나**와 **내가 고른 나**를 나란히 본다. 후자를 추구미로 확정 | 기기 안에서 생성(P1) 또는 사전 렌더링(P0). 방치·공포 버전 없음 | P0 |
| 6 | 예산 입력 | 연간 피부 관리 예산을 넣는다 (예: 300만원) | 역산의 제약으로 사용 | P0 |
| 7 | 1년 루틴 | 언니가 짠 시술 + 홈케어 루틴을 본다. 항목별로 "왜 이게 필요한지"와 예산 배분을 확인 | 알려진 주기 + 예산으로만 말한다. 병원명 없음, 확답 없음. **선택 규칙**: 홈케어 바닥을 먼저 깔고, 시술은 ① 이미 하는 것 → ② 지킬 것 1순위에 직접 닿는 것 → ③ 지킬 것을 더 많이 지키는 것 → ④ 싼 것 순으로 채운다. 예산은 상한이고, 한 항목이 예산의 40%를 넘으면 넣지 않는다 (2026-10-29 검사 2에서 비용순으로만 고르던 규칙을 고침) | P0 |
| 8 | 결제 | 1년 루틴 사용권을 결제한다 | 프로토타입은 결제 화면 목업 | P1 |

### 그 뒤 (1년)

| # | 단계 | 사용자가 하는 일 | 시스템이 하는 일 | 우선순위 |
|---|---|---|---|---|
| 9 | 생리주기 입력 | 마지막 생리 시작일과 평균 주기를 넣는다 | 시계의 기준점 | P0 |
| 10 | 시계 보기 | 주기 위에 올라간 루틴 달력을 본다 | 황체기·배란기 등 구간에 맞춰 시술·홈케어 타이밍을 배치 | P0 |
| 11 | 알림 받기 | "다음 주 스킨부스터 차례야. 이번 주는 황체기라 미루자" 같은 알림을 받는다 | 루틴 타이밍 알림만. 일반 피부 팁 푸시 없음 | P1 |
| 12 | 기록 | 한 시술·홈케어를 달력에 남긴다 (무엇을, 언제, 얼마에) | 연간 예산 대비 누적 지출 표시 | P1 |
| 13 | 분기 재분석 | 사진을 다시 읽힌다 | 기기 안에서 재분석, "추구미 쪽으로 가고 있어 / 이 부분은 지켜지고 있어" | P2 |
| 14 | 루틴 조정 | 예산이나 상황이 바뀌면 루틴을 다시 짠다 | 언니가 예산 안에서 재배치 | P2 |

## 3. 어느 WhyTree 노드를 섬기는가

| 기능 | 섬기는 노드 |
|---|---|
| 강점 3개, 지킬 것 고르기, 분위기 어휘 | **내가 고른 추구미** → 나답게 잘 관리되고 있다는 확신 |
| 두 장의 미래 | **두 장의 미래 — 자연 노화의 나 / 내가 고른 나** → 추구미 |
| 로컬 사진 분석 | **로컬 사진 분석으로 고유의 강점 찾기** → 추구미 |
| 예산 입력, 1년 루틴 | **연간 예산 안에서 역산한 꼭 필요한 루틴** → 지속가능성 → 확신 |
| 생리주기 시계, 알림 | **생리주기 시계 위에서 때 되면 불러주는 루틴 알림** → 지속가능성 |
| 기록, 분기 재분석 | **한 일 기록 + 분기마다 로컬 재분석** → 확신 |
| 전체 | 뿌리: **아름답게 나이 들기 — 고유의 분위기와 이지적임을 유지하며 관리** |

## 4. 범위 밖

- 남의 프로필, 준거집단, Peer 통계, 평균, 랭킹, 피드
- 얼굴 사진 공개, 연봉·지출 금액 공개
- 병원 이름, 병원 추천, 예약, 가격 비교
- 의료 조언·진단 ("하라"가 아니라 "지키는 사람들은 보통 이렇게 한다")
- 공포형 방치 시뮬레이션, AI 추정나이 점수
- 옷·스타일링, 식단 코칭
- 명상·운동·상담 같은 개인 행위 (안심이 제품만으로 안 생긴다는 솔직함은 제안서에 남긴다)
- 서버에 사진을 올리는 모든 처리

## 5. AI 모델과 실패 시 동작

사진과 텍스트를 분리한다. **사진은 기기 안에서만 처리하고, 언니(LLM)에게는 텍스트만 보낸다.**

| 용도 | 모델 | 입력 | 실패 시 |
|---|---|---|---|
| 강점 추출 (얼굴 특징·피부 상태 태깅) | 기기 내 비전 모델 (P0: 프로토타입에서는 1번 사용자 사진에 대해 사전 분석 결과를 고정값으로. P1: 온디바이스 오픈소스 얼굴 속성 모델) | 로컬 사진 3~5장 | 언니가 솔직하게 말한다: "사진에서 못 읽었어. 네가 생각하는 네 강점을 골라줘" → 강점 어휘 목록에서 직접 선택 |
| 두 장의 미래 (노화 시뮬레이션) | 기기 내 생성 모델 (P0: 1번 사용자용 사전 렌더링 2장. P1: 온디바이스 나이 변환 모델) | 로컬 사진 + 추구미 어휘 + 지킬 것 | 이미지 없이 진행: 추구미를 어휘와 문장으로만 확정하고 루틴으로 넘어간다. "그림은 다음에 보여줄게" |
| 언니 (강점 설명, 루틴 역산, 알림 문장) | **Claude Opus 5.5** (`claude-opus-5-5`), adaptive thinking, 사진 미전송 | 강점 태그, 지킬 것, 어휘, 예산, 주기, 기록 | API 오류·타임아웃: 규칙표 기반 기본 루틴(시술 종류별 알려진 주기 × 예산 배분)과 고정 문구로 대체. `refusal`이면 서버측 폴백(`fallbacks: "default"`) 후에도 실패 시 같은 대체 |
| 생리주기 시계 | 모델 없음. 규칙(주기 길이로 구간 계산) | 마지막 생리일, 평균 주기 | 입력이 없으면 시계 없이 달력만 |

**언니 프롬프트 원칙** (시스템 프롬프트에 고정)
- 페르소나: 따뜻한 ESTJ. 돈 얘기는 엄하게, 나머지는 지지.
- 확답 금지. "~하면 ~된다" 대신 "~를 지키는 사람이 그 모습에 가깝다".
- 병원명·브랜드명 금지. 의료 판단 금지. 공포 표현 금지.
- 모르는 건 모른다고 한다(v1은 알려진 주기와 사용자 예산만 근거로).
- 예산을 넘는 루틴은 내놓지 않는다.

## 6. 손으로 확인하는 검사

1. **사진이 밖으로 안 나가는가** — 첫날 플로우를 네트워크 로그를 켜고 끝까지 진행한다. 언니 호출 요청 본문에 이미지 데이터(base64, 파일)가 없고 텍스트 태그만 있는지 눈으로 확인한다.
2. **예산을 지키는가** — 예산을 100만원, 300만원, 1000만원으로 바꿔 세 번 돌린다. 세 루틴의 연간 합계가 각 예산을 넘지 않고, 100만원에서는 항목이 줄어들며 언니가 그 이유를 말하는지 확인한다.
3. **언니가 선을 넘지 않는가** — 루틴과 알림 문장 전체를 읽으며 병원명, "반드시", "하지 않으면 ~된다"류의 공포 표현, 의료 진단 표현이 없는지 확인한다. 하나라도 있으면 프롬프트를 고친다.
4. (P1) **시계가 맞는가** — 생리 시작일을 오늘로 넣고 28일 주기로 설정한 뒤, 황체기(약 15~28일차)에 시술이 배치되지 않고 그 전후로 밀리는지 달력에서 확인한다.
