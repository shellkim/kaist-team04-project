# 버그 수정 및 회귀 테스트 보고서

## 1. 버그 원인 분석

### 발견된 문제
사용자가 재질문에 "기억나지 않아"라고 응답했을 때, 이 응답을 시술명으로 저장하는 버그 발생

### 근본 원인
`app.js`의 `proceedToTable()` 함수에서:
```javascript
if (value) {
  state.extractedTreatments[treatmentIdx][field] = value;
}
```
- 사용자 응답이 비어있지 않으면 무조건 필드에 대입
- 정보 부재를 나타내는 응답("기억나지 않아", "모르겠어" 등)을 구분하지 못함
- 다른 필드값(예: 비용, 시술 시기)은 유지되지만, 잘못된 시술명이 저장됨

## 2. 수정 내용

### Spec 보완
`docs/specs/sorakim-treatment-log.md`의 "4.3 AI 추출 실패 시 처리" 섹션 업데이트:

**추가된 규칙**:
1. 사용자가 실제 정보를 제공한 경우 (예: "보톡스였어") → 필드 업데이트
2. 사용자가 정보를 모른다고 응답한 경우 (예: "기억나지 않아") → 필드는 미입력 상태 유지
3. 다른 필드값은 유지
4. 필수 항목이 미입력인 기록은 최종 저장 시 차단

### 코드 수정 (`prototypes/sorakim/public/app.js`)

**추가된 로직**:
```javascript
// 정보 부재를 나타내는 키워드 감지
const noInfoKeywords = [
  '기억나지 않아', '기억 안 나', '기억이 안 나', '생각 안 나',
  '모르겠어', '모르는데', '모를 것 같은데', '잘 모르겠어',
  '까먹었어', '다 까먹었어', '어떤 것인지 기억 안 나',
  '뭐였는지 모르겠어', '뭐였는지 기억 안 나'
];

// 정보 부재 여부 판단 함수
function isNoInfoResponse(text) {
  const lowerText = text.toLowerCase();
  return noInfoKeywords.some(keyword => lowerText.includes(keyword));
}

// 재질문 응답 처리
if (value && !isNoInfoResponse(value)) {
  // 정보 부재가 아닌 경우만 업데이트
  state.extractedTreatments[treatmentIdx][field] = value;
}
// 정보 부재 응답이면 필드를 업데이트하지 않음 (미입력 유지)
```

**핵심 개선사항**:
- 정보 부재를 나타내는 키워드를 인식하고 필터링
- 빈 응답도 마찬가지로 필드 업데이트 안 함
- 다른 필드값은 영향을 받지 않음
- 저장 시 필수 항목 검증으로 미입력 필드 자동 차단

## 3. 회귀 테스트

### TC1: 정보 부재 응답 (원본 오류 사례)

**입력 흐름**:
1. 초기 입력: "작년에 피부과에서 시술을 받았는데 이름이 기억나지 않아. 비용은 30만 원이었어."
2. AI 추출:
   - `treatment_name`: null (추출 실패)
   - `treatment_date`: "작년" (추출)
   - `cost`: "30만 원" (추출)
3. 재질문: "어떤 시술이었나요?"
4. 사용자 답변: "기억나지 않아"

**예상 결과**:
```javascript
treatment_name: null  // ✓ 미입력 유지 (버그 수정)
treatment_date: "작년"  // ✓ 유지
cost: "30만 원"  // ✓ 유지
```

**실제 결과** (코드 로직 검증):
- `isNoInfoResponse("기억나지 않아")` → `true`
- 조건문 `value && !isNoInfoResponse(value)` → `false`
- `treatment_name` 필드 업데이트 안 함 ✓
- 저장 시 필수 항목 검증: `treatment_name` 없음 → 저장 불가 ✓

**테스트 결과**: ✅ **통과**

---

### TC2: 정상 응답 사례

**입력 흐름**:
1. 초기 입력: "작년에 어떤 시술을 받았는데..."
2. AI 추출:
   - `treatment_name`: null
   - `treatment_date`: "작년"
3. 재질문: "어떤 시술이었나요?"
4. 사용자 답변: "보톡스였어"

**예상 결과**:
```javascript
treatment_name: "보톡스였어"  // ✓ 업데이트됨
treatment_date: "작년"  // ✓ 유지
```

**실제 결과** (코드 로직 검증):
- `isNoInfoResponse("보톡스였어")` → `false`
- 조건문 `value && !isNoInfoResponse(value)` → `true`
- `treatment_name = "보톡스였어"` 업데이트 ✓
- 저장 시 필수 항목 검증: 모두 있음 → 저장 가능 ✓

**테스트 결과**: ✅ **통과**

## 4. 추가 검증사항

### 저장 시 필드 검증
기존 `handleSave()` 함수에서 이미 필수 항목 검증이 구현되어 있음:

```javascript
if (!name || !date) {
  showSaveResult('저장할 항목을 선택해주세요.', 'error');
  return;
}
```

- ✅ 필수 항목(시술명, 시술 시기) 누락 시 저장 차단
- ✅ 다른 시술이 정상이면 독립적으로 저장 가능

### 수정 폼에서의 검증
수정 폼(`handleEditSave()`)에서도 동일한 검증:

```javascript
if (!name || !date) {
  document.getElementById('edit-error').textContent = 
    '시술명과 시술 시기는 필수입니다.';
  return;
}
```

- ✅ 수정 폼에서도 필수 항목 검증

- ✅ 실제 정보 응답 → 필드 업데이트
- ✅ 다른 필드값 유지
- ✅ 저장 시 필수 항목 검증으로 미입력 차단
